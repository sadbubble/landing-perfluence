# Передача проекта

Документ для того, кто продолжит работу в новой сессии или на другой
машине. Здесь то, чего не видно из кода: почему сделано именно так, где
закопаны грабли и что спрашивать у заказчика.

**Обновлено:** 4 сентября 2026 (после подключения формы Qbox)

---

## С чего начать

```bash
npm install
```

```bash
npm run dev
```

Откроется `http://localhost:8080` — **не 5173**, и это важно, см. ниже.

- `/` — лендинг
- `/?manager=test` — он же по персональной ссылке менеджера
- `/d/AG-K7F21` — старый формат ссылки из ТЗ п.5, тоже работает
- `/privacy` — политика обработки персданных
- `/?themes=1` — панель выбора оформления (осталась с этапа согласования)

Переменные окружения **не нужны**: лендинг работает без них.

### Почему порт 8080, а не 5173

Форма заявки — чужая, она живёт на `qbox.telecom.kz` и встраивается в нашу
страницу рамкой. Сервер Qbox отдаёт заголовок `Content-Security-Policy` с
директивой `frame-ancestors`, где перечислены домены, которым разрешено
показывать форму. Из локальных адресов там только `4200`, `4502` и `8080`.

**На 5173 рамка блокируется молча**, и встроенную форму не проверить
вообще. Порт задан в `vite.config.ts` и в `.claude/launch.json`.

## Устройство

React 19 + TypeScript + Vite 8. Одна страница, роутинг на `react-router`.

```
src/
  pages/Landing.tsx     вся страница: состояние, обработчики, разметка секций
  pages/Privacy.tsx     текстовая страница политики
  components/           секции и элементы
  content/ru.ts, kk.ts  ВСЕ тексты; одинаковый набор ключей в обоих файлах
  content/privacy.ts    текст политики отдельно
  lib/dealer.ts         чтение кода менеджера из адреса
  lib/qbox.ts           ТОЧКА ПОДКЛЮЧЕНИЯ QBOX — всё про форму здесь
  lib/phone.ts          нормализация номеров, покрыта тестами (сейчас не у дел)
  index.css             все стили и токены оформления
public/                 картинки и шрифты
_archive/               убранное из проекта, см. ниже
assets-src/fonts/       исходные .otf Helvetica Neue (6 МБ, вне git и сборки)
```

**Тексты только в `content/*.ts`.** В разметке не должно быть ни одной
русской строки: иначе казахская версия рассыплется. Оба файла обязаны
иметь одинаковые ключи — сейчас по 132 с каждой стороны.

**Цвета только через токены в `:root`.** Палитра из гайда заказчика.

## Приём заявок: форма Qbox рамкой

Это главное изменение относительно всего, что было раньше. **Лендинг не
отправляет заявку сам.**

```
кнопка на карточке тарифа
   → модальное окно, внутри рамка с формой Qbox
   → человек заполняет и отправляет прямо там
   → лид в CRM с менеджером и тарифом
```

Человек остаётся на лендинге: адрес в строке браузера не меняется,
параметры не видны. Вся логика — в `src/lib/qbox.ts`, больше нигде.

Из этого решения ушли три вопроса, которые раньше считались блокирующими:
**не нужен CORS, не нужен ключ доступа в коде страницы, не нужен обработчик
на сервере КТ.** Если встретите старые заметки про них — они неактуальны.

### Грабля первая: где стоит «#»

Адрес формы содержит фрагмент с её идентификатором:

```
https://qbox.telecom.kz/forms/#/7a52f500b34f49ad8fd63599e74a2ca5
```

ТЗ «Передача менеджера и тарифа» велит клеить параметры в конец, после
фрагмента. **Так работать не будет:** всё после «#» браузер считает
фрагментом, и `location.search` на стороне формы окажется пустым.

Параметры лида обязаны идти **ДО** решётки. А флаг встраивания `embed=true`
наоборот — **ВНУТРИ** фрагмента, после идентификатора; так его прислали из
Qbox. Получается адрес с двумя строками запроса, и это не опечатка:

```
https://qbox.telecom.kz/forms/?manager=test&Product_name=X#/<id>?embed=true
```

Без `embed=true` рамка остаётся пустой белой. Без параметров до решётки не
приезжают менеджер и тариф. Каждая часть стоит там, где проверена настоящей
заявкой в CRM.

### Грабля вторая: регистр кода менеджера

Коды менеджеров в Qbox строчные (`anna`, `test`). Раньше в `dealer.ts`
стоял `toUpperCase()` — под коды вида `AG-K7F21` из ТЗ п.5. Оставь мы его,
`test` превратился бы в `TEST` и менеджер в CRM не нашёлся бы.

**Регистр не меняется.** Код уходит ровно таким, каким его написали в
ссылке, а сверка остаётся на стороне Qbox.

### Грабля третья: как называется ключ тарифа

Источники расходятся: ТЗ пишет то `Product_name`, то `tariff`, скриншот на
слайде 6 «Инструкции по запуску лидогенерации» показывает `product_name`
строчными.

Правильный ответ подсмотрен в самом Qbox: воронка → Настройки → Поля →
поле «тариф» → Ключ. Там **`Product_name`** с заглавной P. Поле «менеджер» —
`manager`.

Если увидите в презентации `product_name` и захотите «исправить» —
не надо. Тот скриншот, судя по всему, снят с другой воронки.

### Грабля четвёртая: встраивание разрешено не отовсюду

Список доверенных доменов задаёт Qbox своим CSP. `partner.telecom.kz` из
ТЗ п.5 там уже есть — просить их ни о чём не пришлось. Витрины на Vercel
там **нет**, и на ней рамка не покажется.

Поэтому в `qbox.ts` есть `canEmbedForm()`: где встраивание разрешено —
открывается окно с рамкой, где нет — кнопка честно уводит на форму
переходом. Заявка доедет одинаково, разница только в удобстве.

Если КТ выдаст домен, которого нет в списке Qbox, — его туда надо будет
добавить, иначе форма перестанет встраиваться.

### `[unresolved_products]` — не ошибка

В комментарии к каждому лиду появляется пометка вида
`[unresolved_products] - Bereket 4 SIM (без контракта)`. Qbox ищет
совпадение в своём каталоге продуктов и не находит.

На заявку это не влияет: значение записывается в поле «ПРодукт» текстом и
видно целиком. Заказчик уточнял у Qbox — заполнять каталог не нужно и
нельзя, что означает пометка, там не знают.

Отсюда следствие: девять названий в `QBOX_PRODUCTS` — это **текст, который
читают глазами** менеджеры продаж и по которому считают выработку дилеров.
Поэтому они на русском и содержат режим контракта с числом SIM: одно слово
«Bereket» о цене не говорит ничего.

### Что уходит в форму

`manager` и `Product_name`. Больше ничего. Имя, телефон и город собирает
сама форма.

**Кнопки в шапке и в баннерах шлют заявку без тарифа** — человек до
карточек не дошёл и ничего не выбирал.

## Решения, которые легко случайно сломать

### Палитра: два синих, не один

Гайд даёт `#008EFF` как основной. Но **белый текст на нём даёт контраст
3.33 при норме 4.5** — на нём нельзя писать белым. Поэтому:

- `--brand` `#008EFF` — акценты, обводки, подложки, крупная графика;
- `--brand-strong` `#0044BC` — заливка под белым текстом: все кнопки;
- `--brand-light` `#00D9FF` — градиенты, декор и текст на тёмном.

Оба цвета из гайда. Если увидите «странно, почему кнопки тёмно-синие» —
вот почему. Не меняйте на `#008EFF`, не пересчитав контраст.

### Плашка партнёра написана `--brand-light`, и это не случайность

Обязательная плашка «Официальный партнёр» (ТЗ п.3) в подвале написана
голубым, хотя вокруг всё синее. Причина в замере: собственная подложка
плашки осветляет фон до `#08345C`, и на нём `--brand` даёт **3.81 при
норме 4.5** — кегль 11px, послаблений для крупного текста не полагается.

Парадокс в том, что **без подложки** тот же цвет проходит (4.67): её и не
хватило. `--brand-light` на том же фоне даёт 7.47.

Подложка намеренно осталась на `--brand`: она должна быть холоднее текста,
иначе контраст просядет снова.

### У Bereket два переключателя, а не один

Кроме общего «с контрактом / без» на карточке Bereket есть свой —
**2 SIM / 4 SIM**. В Qbox это разные продукты с разными ценами (12 999 /
13 999 против 16 999 / 17 999).

Раньше 4 SIM был строчкой текста под ценой: нажать нельзя, и лендинг
физически не мог сообщить форме, что выбрали именно его. Из четырёх
карточек получается девять вариантов, а не восемь: у акционного Keremet
цена одна, и переключатель контракта на него не влияет.

### Разноцветные шапки тарифов — отменены дважды

Сначала были разноцветные (оранжевый Bereket и т.п.), потом синие по
гайду, потом заказчик вернул разноцветные, потом попросил переделать всю
секцию по своему макету — и сейчас карточки **белые, без цветных шапок**.
Файл `_archive/unused-ui/tariffAccents.ts` — от той версии.

### Шрифт подключается файлами

Helvetica Neue есть только в системах Apple. В `public/fonts/` лежат
четыре начертания в woff2, урезанные до нужных символов: 156 КБ вместо
6,4 МБ исходников. **Казахские буквы `әғқңөұүһі` в них проверены** — это
была главная неизвестность.

Внешних шрифтовых сервисов на странице нет намеренно: страница поедет на
сервер КТ, лишняя зависимость от чужого домена там ни к чему.

### Картинки баннеров подобраны расчётом, а не на глаз

У верхнего и нижнего баннера поверх картинки лежит полупрозрачная вуаль.
Её плотность подбиралась **измерением контраста по реальным пикселям
файла**, а не подгонкой на глаз. Дважды выяснялось, что «выглядит
нормально» означает 2.4–3.9 при норме 4.5.

У нижнего баннера вдобавок кадр прижат к низу (`background-position:
center bottom`): при центрировании яркое свечение из верхней части
картинки ложилось ровно на строку заголовка.

**Если меняете размеры баннеров или текст в них — пересчитайте контраст.**
Геометрия обрезки меняется, и прежний расчёт становится недействителен.

### Мобильные баннеры без картинок

На телефоне широкие кадры обрезаются до полосы, где не остаётся ничего
полезного. Обе картинки на мобильном отключены — там рисуется градиент.
Это и резче, и легче.

### Высота баннера считается от окна, а не от ширины

Верхний баннер занимает ровно высоту окна. Кегль заголовка ограничен
и по высоте: `min(clamp(...), 8.5svh)`. Без этого на широком, но невысоком
окне (Windows со 125% масштабом даёт около 1360×625) низ баннера уезжал
за экран.

### Модальное окно: Esc больше не закрывает

В окне теперь чужая рамка, и из этого следуют два ограничения, которые с
нашей стороны починить нельзя:

- **Esc не закрывает окно**, пока курсор внутри формы: события клавиатуры
  остаются в чужой рамке и до нас не доходят;
- **Tab выводит фокус из окна** на страницу: ловушка фокуса не видит
  содержимое чужого домена.

Крестик и клик по затемнению работают всегда. Поэтому крестик доведён до
44×44 — он стал единственным надёжным способом выйти.

`sandbox` на рамке намеренно не стоит: в коде, присланном из Qbox, его
нет, а проверить, не ломает ли он отрисовку, мы не можем — содержимое
чужой рамки нам не видно.

## Что лежит в `_archive/`

Ничего оттуда не используется. Перенесено, а не удалено.

| Папка | Что там | Почему убрано |
|---|---|---|
| `backend/` | Схема БД, RLS, Edge Function приёма заявок, админка с отчётами и выгрузкой в Excel | Заказчик отменил бэкенд: заявки идут в Qbox |
| `figma/` | Исходный экспорт из Figma Make | Код с тех пор переписан полностью |
| `unused-ui/` | Секция «Преимущества», логотип, цвета шапок тарифов | Убраны по просьбе заказчика |
| `qbox-probe/` | Страница-проверка встраивания формы | Своё дело сделала; в сборку попадала зря |

В `backend/` лежит рабочая реализация: миграции, политики доступа, приём
заявок с валидацией, антиспамом и дедупликацией, панель менеджера с
фильтрами и выгрузкой по дилерам. Если Qbox не подойдёт — это готовая
замена, а не черновик.

**В дереве, но без дела** лежат `components/LeadForm.tsx`, `lib/api.ts` и
`lib/config.ts` — наша прежняя форма и отправка на бэкенд. Из сборки они
уже выпали: их никто не импортирует. `components/Modal.tsx` наоборот
**используется** — в нём теперь рамка с формой Qbox, не трогать.

## Открытые вопросы к заказчику

- **Согласие на обработку персданных** в форме Qbox. Его там нет, а по
  закону РК оно обязательно. Главный блокер, и закрыть может только Qbox.
- **Состав тарифов не показывается.** «160+ каналов», «7 онлайн-кинотеатров»
  есть в данных, но новый макет карточек их не выводит. ТЗ п.4 состав
  требует — там колонка так и называется, «Состав / условия».
- **Тексты.** Заказчик говорил, что часть надо поменять, но какие именно —
  не сказал. Тексты нижнего баннера писались нами и не утверждены.
- **Правый нижний угол подвала пуст.** Там был копирайт (спорный на домене
  КТ), потом телефон — оба отклонены.
- **Жёлтый акцент.** Сейчас `#FFE14D`, подобранный на глаз. Измеренное
  значение из гайда — `#F1B13E`, снято с плашки «БӘРІ ҚОСЫЛҒАН» на примере
  баннера. Менять по слову заказчика.
- **Телефон отдела продаж** — нигде на странице нет.
- **Лицензия на Helvetica Neue** для веба. Шрифт коммерческий.
- **Передача UTM-меток.** Лендинг их читает, но в форму не шлёт. Qbox их
  принимает и ждёт для лендингов формат `utm_source = landing_<name>` —
  имя надо согласовать.

## Как проверять работу

В проекте нет визуальных тестов, поэтому проверка — измерениями в браузере.
Что стоит прогонять после правок оформления:

- горизонтальная прокрутка: `document.documentElement.scrollWidth - clientWidth`
  должно быть `0` на 320, 375, 768, 1024, 1440 — **и в русской, и в
  казахской версии.** Сейчас в казахской при 320 есть 27px, см. `TODO.md`;
- высота верхнего баннера не больше высоты окна;
- контраст текста не ниже 4.5 (для крупных заголовков — 3.0);
- цели для пальца не меньше 44px;
- обе языковые версии.

**Считайте контраст через canvas, а не разбором строки цвета.** Chrome
отдаёт `color-mix()` в виде `color(srgb 0 0.56 1 / 0.15)`, и наивный
разбор читает `0 0.56 1` как значения 0–255 — получается почти чёрный, и
все числа оказываются мусором. Надёжный способ: залить цвет в canvas
поверх известного фона и прочитать пиксель.

### Как проверить привязку, не уходя со страницы

В режиме разработки в `Landing.tsx` есть крючок `window.__qboxHook`: если
присвоить ему функцию, переход на форму не произойдёт, а адрес придёт в
неё. В сборку крючок не попадает.

Когда форма открывается рамкой, проще смотреть прямо в DOM:
`document.querySelector('.qbox-frame').src`.

`npm test` покрывает только нормализацию телефонов — семь случаев, включая
городские номера Алматы, которые когда-то ошибочно проходили как мобильные.
Сама нормализация сейчас не используется: телефон проверяет форма Qbox.

Скопируйте целиком в первое сообщение нового чата. Первоисточники —

```
Продолжаем работу над лендингом, начатую в другой сессии. Проект лежит в
C:\work\landing-perfluence.

Прочитай сначала три документа в корне: HANDOFF.md (как устроено и почему

Коротко о проекте: одностраничный лендинг ТОО «Perfluence», официального
партнёра АО «Казахтелеком», для сбора заявок на подключение интернета и ТВ.
Заявку принимает форма Qbox, встроенная в страницу рамкой; менеджер и тариф
передаются ей параметрами адреса. Ключевое требование — каждая заявка
привязывается к менеджеру, приведшему клиента, по персональной ссылке вида
/?manager=anna. React 19 + TypeScript + Vite, две языковые версии.

   относительно окна, размеры целей для пальца. За этот проект «выглядит
   нормально» трижды означало контраст ниже нормы, и каждый раз это ловил
   расчёт, а не взгляд.
```
