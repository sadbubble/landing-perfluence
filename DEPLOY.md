# Публикация на Vercel

Проект к деплою готов: сборка проверена как статика, SPA-переходы и ссылки
дилеров работают, все картинки попадают в `dist/`.

## Один раз — вход

```bash
npx vercel login
```

Откроется браузер (или придёт код на почту) — это интерактивный шаг,
выполнить его может только человек.

## Деплой

Черновая ссылка для показа:

```bash
npx vercel
```

Боевая:

```bash
npx vercel --prod
```

На первый вопрос про настройки отвечайте «нет» — Vite определяется
автоматически, `vercel.json` в проекте уже задаёт нужные правила.

## Что важно знать про эту сборку

**Переменные окружения не нужны.** Лендинг работает без ключей Supabase:
тарифы берутся из текстов в коде, база пока не подключена.

**Форма заявки на этой ссылке отправляться не будет** — покажет ошибку
отправки. Это ожидаемо: Edge Function не задеплоена, база на паузе.
Для показа дизайна руководителю это не мешает; когда дойдём до бэкенда,
добавим переменные в настройках проекта Vercel:

```
VITE_SUPABASE_URL
VITE_SUPABASE_ANON_KEY
```

**Страница `/admin` покажет «Бэкенд не настроен»** — тоже ожидаемо.

- `https://<адрес>/` — лендинг

## Выкладка на сайт Казахтелекома: telecom.kz/perfluence

Боевой адрес — `https://telecom.kz/perfluence/` (подпапка основного сайта
КТ, а не поддомен; решение заказчика, октябрь 2026). Выкладывает человек
со стороны КТ: сначала на тестовый стенд, потом на telecom.kz, **без
чтения инструкций и без настройки сервера**. Под это и сделана сборка:

```bash
npm run build:telecom
```

Собирает в `dist-telecom/` **с относительными путями** (`vite --base ./`):
папка работает из любого места — `/perfluence/`, `/ru/perfluence/`, папка
тестового стенда — без пересборки и без правил на сервере. Настоящий путь
страница узнаёт сама по адресу своего скрипта (`src/lib/base.ts`).
Обычная `npm run build` по-прежнему собирает под корень — для Vercel.

Цена относительных путей: внутри папки работает только её корень.
Поэтому нет ни страницы политики (убрана по решению заказчика — лендинг
берёт только телефон), ни ссылок `/d/КОД`: менеджерам раздаются только
`…/perfluence/?manager=КОД`. Адрес папки без слэша (`/perfluence`)
обычный сервер дополняет слэшем сам; на случай, если нет, — короткий
скрипт в `index.html`.

На тестовом стенде домен другой, и Qbox встраивать туда форму не даст —
кнопка откроет форму отдельной страницей Qbox, заявки доходят. Окном
форма откроется на telecom.kz. Под окном формы — ссылка «Откройте её
отдельно» на случай, если встраивание заблокирует сам сайт (CSP,
`www.telecom.kz`).

Выгрузка вне репозитория:

- `C:\work\perfluence-telecom-kz.zip` — **только папка `perfluence`**, её и
  выкладывают; ничего лишнего (README в ней оказался бы на сайте);
- `C:\work\perfluence-telecom-kz-source.zip` — исходники без ТЗ,
  документов, `_archive/` и старой формы, с коротким README;
- `C:\work\perfluence-telecom-kz\` — то же распакованным.

**Сборка в архиве сделана из исходников выгрузки чистой установкой
`npm ci`**, а не из рабочей папки. Разница есть: в рабочей папке Tailwind
находит имена классов в `_archive/` и добавляет в CSS девять лишних утилит
(`.absolute`, `.ring`, `.table`…), а зависимости стоят по `pnpm-lock.yaml`,
а не по `package-lock.json` (Vite 8.3.4 против 8.2.2, React 19.3.0 против
19.2.8). Высоты карточек и баннера в обеих сборках совпадают до пикселя.

Проверка «как выложит человек» — конфиг `static-4200` в
`.claude/launch.json`: простой сервер Python без каких-либо правил. Его
каталог — во временной папке сессии; для новой проверки укажите свой, с
папкой сборки внутри (например, `perfluence/` и `ru/perfluence/`).

## Поддомен Казахтелекома

Когда согласуют `*.telecom.kz`: в проекте Vercel → Settings → Domains
добавить домен и прописать у регистратора CNAME, который покажет Vercel.
Код при этом не меняется.
