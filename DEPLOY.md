# Публикация на Vercel

Витрина для показа руководству. Сборка статическая, все картинки попадают
в `dist/`.

## Один раз — вход

```bash
npx vercel login
```

Откроется браузер (или придёт код на почту) — это интерактивный шаг,
выполнить его может только человек.

## Деплой

Черновая ссылка для показа:

```bash
npx vercel
```

Боевая:

```bash
npx vercel --prod
```

На первый вопрос про настройки отвечайте «нет» — Vite определяется
автоматически, `vercel.json` в проекте уже задаёт нужные правила.

## Что важно знать про эту сборку

**Переменные окружения не нужны.**

**Форма заявки здесь открывается переходом на сайт Qbox, а не окном**:
домена Vercel нет в списке Qbox. Заявки доходят.

## Ссылки для показа

После деплоя Vercel выдаст адрес вида `landing-perfluence-xxx.vercel.app`.

- `https://<адрес>/` — лендинг
- `https://<адрес>/?manager=test` — он же по персональной ссылке менеджера

## Выкладка на сайт Казахтелекома: telecom.kz/perfluence

Боевой адрес — `https://telecom.kz/perfluence/` (подпапка основного сайта
КТ, а не поддомен; решение заказчика, октябрь 2026). Выкладывает человек
со стороны КТ: сначала на тестовый стенд, потом на telecom.kz, **без
чтения инструкций и без настройки сервера**.

**КТ принимает исходники, а не готовую сборку**, — папкой как у других их
лендингов (`C:\work\internet-figma` — образец): `src/`, `public/`,
`index.html`, `package.json`, `pnpm-lock.yaml`, `tsconfig.json`,
`vite.config.ts`, `.mise.toml` (Node 22, pnpm 10.34.3), `.gitignore`,
`.gitattributes`; без `node_modules` и `dist`. Собирают сами:

```bash
pnpm install
pnpm build
```

Сборка в `dist/` **с относительными путями** — `base: "./"` задан прямо в
`vite.config.ts`, так что обычная команда build их и даёт: папка работает
из любого места — `/perfluence/`, `/ru/perfluence/`, тестовый стенд, корень
домена — без правил на сервере. Настоящий путь страница узнаёт сама по
адресу своего скрипта (`src/lib/base.ts`). Та же сборка годится и для Vercel.

Цена относительных путей: внутри папки работает только её корень.
Поэтому нет ни страницы политики (убрана по решению заказчика — лендинг
берёт только телефон), ни ссылок `/d/КОД`: менеджерам раздаются только
`…/perfluence/?manager=КОД`. Адрес папки без слэша (`/perfluence`)
обычный сервер дополняет слэшем сам; на случай, если нет, — короткий
скрипт в `index.html`.

На тестовом стенде домен другой, и Qbox встраивать туда форму не даст —
кнопка откроет форму отдельной страницей Qbox, заявки доходят. Окном
форма откроется на telecom.kz. Под окном формы — ссылка «Откройте её
отдельно» на случай, если встраивание заблокирует сам сайт (CSP,
`www.telecom.kz`).

Выгрузка вне репозитория: `C:\work\perfluence-telecom-kz.zip` (и то же
распакованным в `C:\work\perfluence-telecom-kz\`) — папка проекта
`perfluence` без ТЗ, документов и `_archive/`.

`pnpm-lock.yaml` в выгрузке получен командой `pnpm import` из нашего
`package-lock.json`: pnpm ставит ровно те версии, на которых всё проверено.
В репозитории по-прежнему npm.

Сборка у КТ отличается от сборки в репозитории только CSS: в рабочей папке
Tailwind находит слова вроде `table`, `ring` в документах и архиве и
добавляет семь служебных классов. Разметка их не использует; слепки обеих
сборок совпадают (проверять — дождавшись загрузки шрифтов, иначе страница
мерится в запасном шрифте и «расходится» на пиксели).

Проверка «как выложит человек» — конфиг `static-4200` в
`.claude/launch.json`: простой сервер Python без каких-либо правил. Его
каталог — во временной папке сессии; для новой проверки укажите свой, с
папкой сборки внутри (например, `perfluence/` и `ru/perfluence/`).

## Поддомен Казахтелекома

Когда согласуют `*.telecom.kz`: в проекте Vercel → Settings → Domains
добавить домен и прописать у регистратора CNAME, который покажет Vercel.
Код при этом не меняется.
